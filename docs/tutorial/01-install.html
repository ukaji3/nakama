第 1 章 インストールとサインイン

nakama 本体をパソコンに置き、AWS にサインインするところまでを行います。ここまで済めば、以降の章のコマンドが実行できます。

1. Windows にインストールする

nakama は 1 つの実行ファイル (nakama.exe) だけで動きます。インストーラーはありません。ファイルを好きな場所に置いて、そこを Windows に教えるだけです。

  1. ダウンロードする。 Releases ページを開き、最新版の nakama_<バージョン>_windows_amd64.zip をダウンロードします。checksums.txt も一緒にダウンロードしてください。

    amd64 と arm64 のどちらを選ぶか

    ふつうの Windows パソコンは amd64 です。Surface Pro X などの ARM 版 Windows を使っている場合だけ arm64 を選びます。分からなければ、PowerShell で次を実行してください。AMD64 と表示されれば amd64 です。

    $env:PROCESSOR_ARCHITECTURE

  2. ファイルが壊れていないか確認する (任意ですが推奨)。 まずダウンロードしたフォルダーで PowerShell を開きます。エクスプローラーでそのフォルダーを開き、ファイルのない余白で Shift を押しながら右クリックし、「PowerShell ウィンドウをここで開く」(Windows 11 では「ターミナルで開く」) を選びます。

    PowerShell で実行 (2 つの値を並べて表示します)

    (Get-FileHash .\nakama_0.17.0_windows_amd64.zip -Algorithm SHA256).Hash
Select-String -Path .\checksums.txt -Pattern windows_amd64.zip

    表示された 2 つの英数字列が同じなら正常です (大文字・小文字の違いは無視して構いません)。ファイル名の 0.17.0 は、ダウンロードしたバージョンに読み替えてください。

  3. 展開する。 zip ファイルを右クリックして「すべて展開」を選びます。中に nakama.exe が入っています。

  4. 置き場所を決めて移動する。 例として、自分のユーザーフォルダーの下に bin というフォルダーを作って置きます。管理者権限が要らないので安全です。

    「すべて展開」を使うと nakama_0.17.0_windows_amd64 のようなフォルダーが新しく作られ、その中に nakama.exe が入っています。まずそのフォルダーへ移動してください。

    PowerShell で実行 (展開先へ移動 → 置き場所を作る → 移動)

    cd .\nakama_0.17.0_windows_amd64
New-Item -ItemType Directory -Force "$env:USERPROFILE\bin"
Move-Item .\nakama.exe "$env:USERPROFILE\bin\nakama.exe"

    フォルダー名はバージョンによって変わります。cd .\nakama_ まで打って Tab キーを押すと、残りが自動で補完されます。「パスが見つかりません」と出る場合は、dir と打って、いまいる場所に何があるかを確認してください。

  5. 置き場所を Windows に教える (PATH に追加)。 これをしておくと、どのフォルダーからでも nakama と打つだけで実行できます。

    PowerShell で実行 (自分のユーザーにだけ設定します)

    [Environment]::SetEnvironmentVariable(
  "Path",
  [Environment]::GetEnvironmentVariable("Path", "User") + ";$env:USERPROFILE\bin",
  "User")
    設定後は新しいウィンドウを開いてください

    この設定は今開いているウィンドウには反映されません。PowerShell を閉じて、もう一度開いてから次の手順に進みます。

    画面から設定したい場合は、Windows キーで「環境変数」と検索 →「環境変数を編集」→ ユーザー環境変数の Path を選んで「編集」→「新規」で C:\Users\<あなたの名前>\bin を追加します。

    上のコマンドを実行したあと、値の先頭に ; が付くことがあります (もともと Path が空だった場合)。動作に影響はありません。

  6. 動作を確認する。 新しい PowerShell で次を実行します。

    PowerShell で実行

    nakama version
    0.17.0 (6c34716, 2026-09-03T17:35:42Z)

    バージョンが表示されれば成功です。用語 'nakama' は、コマンドレット...として認識されません と出る場合は、PATH の設定か、ウィンドウの開き直しができていません。

どんなコマンドがあるかを見る

いつでも --help を付けると、そのコマンドの説明とオプションが表示されます。迷ったらまずこれを見てください。

nakama aws --help
nakama aws create --help

2. macOS / Linux の場合

やることは同じです。tar.gz を展開して、PATH の通った場所に置きます。

macOS / Linux のターミナルで実行 (Linux amd64 の例)

VERSION=0.17.0
curl -fsSL "https://github.com/ukaji3/nakama/releases/download/v${VERSION}/nakama_${VERSION}_linux_amd64.tar.gz" -o /tmp/nakama.tar.gz
mkdir -p /tmp/nakama && tar -xzf /tmp/nakama.tar.gz -C /tmp/nakama
sudo install -m 0755 /tmp/nakama/nakama /usr/local/bin/nakama
nakama version

macOS では linux の代わりに darwin、Apple Silicon なら darwin_arm64 (または両対応の darwin_universal) を選びます。

3. AWS にサインインする

nakama を使うには、まず「どの AWS アカウントとして操作するか」を決めます。nakama aws login を実行すると、ブラウザが開いて AWS のサインイン画面が表示されます。

PowerShell で実行

nakama aws login

次のように進みます。

  1. ブラウザが自動で開きます (開かない場合は、画面に表示された URL を自分でブラウザに貼り付けます)。

  2. AWS のサインイン画面が出たら、ふだん使っている AWS のユーザーでログインします。すでにブラウザで AWS コンソールにログイン済みなら、確認画面だけで済みます。

  3. 「許可」を選ぶと、PowerShell の側に戻ってサインイン完了が表示されます。このとき profile という言葉が出ますが、これは「どの AWS アカウントとして操作するか」の記録です (5 節で説明します)。いまは気にしなくて構いません。

なぜブラウザを使うのか

アクセスキーのような長期間有効な秘密の文字列をパソコンに置かずに済むからです。nakama は AWS 公式の aws login と同じ方式 (OAuth 2.0 + PKCE + DPoP) を自前で実装しているため、aws コマンドをインストールしなくてもサインインできます。取得した一時的な認証情報は ~/.aws/login/cache/ (Windows では C:\Users\<あなた>\.aws\login\cache\) に保存され、あなたの ~/.aws/config は書き換えません。

サインインできない場合

ログインには AWS の管理ポリシー SignInLocalDevelopmentAccess が、あなたの IAM ユーザーまたはロールに付いている必要があります。付いていないと、ブラウザ側で拒否されます。会社のアカウントであれば、AWS の管理者に「この管理ポリシーを付けてほしい」と依頼してください。

AWS の利用経験がある人向けの補足: 権限を変えられない場合は、AWS SSO や環境変数などふだん使っている別の方法で認証情報を用意しても構いません (nakama は標準的な AWS の認証情報をそのまま使えます)。初めての場合は、管理者に SignInLocalDevelopmentAccess の付与を依頼する方法だけ知っておけば十分です。

サインインできたかを確かめる

PowerShell で実行

nakama aws doctor

credentials の行に、どの AWS アカウントとして動いているかが表示されます。ok なら成功です。この画面の読み方は第 7 章で詳しく説明します。

SSH 越しやブラウザのない環境では

ブラウザを起動できないパソコン (別のサーバーに SSH で入って作業している場合など) では --remote を付けます。表示された URL を手元のブラウザで開き、そこに出る確認コードを貼り付ける方式になります。

nakama aws login --remote

4. 有効期限と再サインイン

サインインの有効期限は最長 12 時間です。期限が切れると、コマンドを実行したときに「期限切れなのでもう一度サインインしてほしい」というエラーが出ます。その場合はもう一度実行するだけです。

nakama aws login
ポート転送を使っていた場合

再サインインしたあとに nakama aws tunnel restart <名前> を実行すると、設定を変えずに転送をつなぎ直せます (第 5 章)。

5. 複数の AWS アカウントを使う

仕事用と個人用など、複数の AWS アカウントを切り替えて使う場合は profile を使います。サインインしたセッションに名前を付けて保存し、あとから選び直せます。

PowerShell で実行 (アカウント A とアカウント B を登録する例)

nakama aws login                        # アカウント A にサインイン
nakama aws profile save --name work      # 「work」という名前で保存

nakama aws login                        # アカウント B にサインイン
nakama aws profile save --name personal  # 「personal」として保存

nakama aws profile list                  # 保存したものを一覧表示
nakama aws profile load work              # 以降のコマンドは work を使う
nakama aws profile unload                 # 選択を解除 (既定の認証方法に戻す)
nakama aws profile delete personal        # 登録を削除

profile list は次の列を表示します。

列意味
ACTIVE* が付いているものが、いま nakama が使うアカウントです
ACCOUNTAWS アカウント ID (12 桁の数字)
ALIAS--name で付けた呼び名
IDENTITYどのユーザー / ロールとして動くか
SAVED保存した日時
STATUSまだ使えるか、期限切れかどうか
保存されるのは秘密の情報ではありません

nakama が保存するのはセッションの識別子だけで、パスワードやアクセスキーではありません。実際の一時認証情報は AWS 公式と同じ場所 (~/.aws/login/cache/) にあり、nakama はそれを読み書きします。~/.aws/config には一切手を触れません。

意図しないアカウントに作らないための安全策

profile load したセッションが期限切れなどで使えない場合、nakama は別のアカウントに勝手に切り替えずエラーで止まります。「仕事用のつもりで個人用アカウントにサーバーを作ってしまう」ことを防ぐためです。

6. つまずきやすい点

症状原因と対処
用語 'nakama' は ... 認識されません PATH の設定が反映されていません。PowerShell を閉じて開き直してください。それでも駄目なら、置き場所を絶対パスで実行して確認します (例: & "$env:USERPROFILE\bin\nakama.exe" version)
ブラウザが開かない 画面に表示される URL を手でブラウザに貼り付ければ同じことができます。SSH 経由なら --remote を使ってください
証明書のエラーが出る 会社のネットワークが通信を検査している場合に起きることがあります。nakama 本体は Windows の証明書設定を読むので通常は問題ありませんが、詳しくは第 2 章を読んでください
アカウントが違う nakama aws doctor の credentials 行で、いまどのアカウントとして動いているかを確認できます。profile load で切り替えます
