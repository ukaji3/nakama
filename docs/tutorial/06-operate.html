第 6 章 日々の運用

作った環境を長く使うための操作です。まず覚えるのは stop だけで十分です (使い終わったら止める)。

1. 起動と停止 (毎日使うもの)

PowerShell で実行

nakama aws list                # いま何があるか、動いているか
nakama aws stop dev01          # 作業終了。中身は残ります
nakama aws start dev01         # 翌日また使う
停止しても消えません

stop は電源を切るだけです。インストールしたツール、書いたコード、設定はすべて残ります。翌日 start すれば同じ状態から再開できます。止めれば課金の大部分が止まります (第 3 章)。

外向き通信の中継役 (NAT インスタンス) も、すべての環境が停止すると自動で止まります。手動での操作は不要です。

list の表示はこうなります。

NAME     INSTANCE_ID          STATE    TYPE    INSTANCE_TYPE  DISTRIBUTION_DOMAIN
dev01    i-0123456789abcdef0  running  VSCODE  t3.medium      d111111abcdef8.cloudfront.net
box01    i-0abcdef1234567890  stopped  BARE    t3.medium      -
列意味
STATErunning = 起動中 / stopped = 停止中
TYPEVSCODE = 通常の環境 / BARE = --bare で作った環境 / NAT = 中継役 (--show-nat を付けたときだけ表示)

2. バックアップと復元

ディスクの内容をまるごと控えておけます。大きな変更をする前に取っておくと安心です。

PowerShell で実行

nakama aws backup create dev01                                  # ラベルは自動 (日時)
nakama aws backup create dev01 --label before-upgrade --note "アップグレード前"
nakama aws backup create dev01 --keep 5                         # 古い世代を 5 つまでに整理
nakama aws backup list dev01                                    # 一覧
nakama aws backup list                                           # 全環境の一覧 (NAME 列付き)
nakama aws backup note dev01 --label before-upgrade --note "動作確認済み"
nakama aws backup delete dev01 --label before-upgrade
LABEL                 CREATED_AT            STATE       GiB    NOTE
before-upgrade        2026-09-12T22:10:33Z  completed   30     アップグレード前
20260913-001204       2026-09-13T00:12:04Z  pending     30

STATE が pending の間はまだ作成中で、completed になれば復元に使えます。

復元する

nakama aws restore dev01                       # 最新のバックアップに戻す
nakama aws restore dev01 --label before-upgrade  # 世代を指定して戻す

実行すると確認を求められます。

Restore nakama instance "dev01" in place? This deletes the current root volume. [y/N]:
restore は現在の内容を消します

復元はディスクを置き換える操作です。バックアップ以降に書いた内容は失われ、元に戻せません。実行前に nakama aws backup create dev01 でいまの状態も控えておくと安全です。--yes で確認を省略できますが、意図が確実なときだけにしてください。

3. アップデート

OS のパッケージと code-server を最新にします。

nakama aws update dev01
nakama aws update dev01 --keep 5 --yes    # 自動バックアップを 5 世代までに制限し、確認を省略

内部では次の順に進みます。

  1. バックアップを自動取得します (失敗しても戻せるようにするため)。

  2. 停止していた場合は起動します。

  3. OS のパッケージ更新 (apt dist-upgrade 相当) と code-server の最新版導入を実行します。

  4. 更新の内容によって再起動が必要な場合は再起動します。

  5. 元の電源状態に戻します (もともと停止していた環境は、また停止します)。

--bare の環境では OS の更新だけ

code-server が無いので、その部分は行われません。

時間がかかることがあります

更新の量によって数分から十数分かかります。途中で中断しないでください。うまくいかなかった場合は、直前に取られたバックアップから restore できます。

4. 大きさとディスクの変更

ディスクを増やす

nakama aws edit dev01 --ebs 60

ディスクを 60 GiB に拡張します。ディスク側の拡張だけでなく、OS 側での認識 (パーティションとファイルシステムの拡張) まで自動で行われます。

縮小はできません

AWS の仕様上、ディスクは大きくすることしかできません。現在より小さい値は指定できません。

インスタンスの型を変える

nakama aws edit dev01 --instance-type m6a.2xlarge
nakama aws edit dev01 --instance-type t3.medium --yes    # 確認を省略

停止 → 型の変更 → 元の電源状態へ復帰、という順に自動で進みます。起動中の環境に対して実行すると、いったん停止するため作業中のプロセスは終了します。

ARM と Intel/AMD の間は変更できません

t4g (ARM) から t3 (Intel/AMD) のような変更は、ディスクの中身が対応していないためできません。第 4 章も参照してください。

5. 削除

nakama aws delete dev01

確認のあと、その環境に属する AWS のリソース (EC2、ディスク、CloudFront、WAF の関連設定、SSM のパラメータ) を削除します。

中身も消えます

delete はディスクも削除するため、その環境に置いていたコードやデータは失われます。必要なものは事前に git へ push するか、backup create を取ってください。

なお、backup で取ったスナップショットは環境の削除後も残ります (別途 backup delete で消せます)。

オプション用途
--yes / -y確認を省略します
--force「もう存在しない」というエラーを無視して先に進みます (途中で失敗した削除の後片付けに使います)
土台 (init で作ったもの) は残ります

delete は個々の環境だけを消します。VPC や WAF などの共通部分はそのままなので、また create すればすぐ作れます。共通部分まで消したい場合は AWS コンソールから手動で削除してください。
