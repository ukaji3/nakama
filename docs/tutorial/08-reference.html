第 8 章 コマンド早見表

全コマンドとオプションの一覧です。手元で確認したいときは、どのコマンドにも --help を付けられます。

1. 共通オプション

オプション意味
-o, --output <形式>出力形式。table (既定) / json / yaml
-v, --verbose詳細ログを表示 (原因調査に使います)
-h, --help使い方を表示

2. コマンド一覧

サインインとアカウント

コマンド説明主なオプション
nakama aws loginブラウザ経由でサインイン--remote (URL 表示 + コード貼り付け方式)、--name <別名>
nakama aws profile saveいまのセッションを保存--name <別名>
nakama aws profile list保存済みを一覧—
nakama aws profile load <名前>使うアカウントを選択—
nakama aws profile unload選択を解除—
nakama aws profile delete <名前>登録を削除—
nakama versionバージョン表示—

土台とアクセス制御

コマンド説明主なオプション
nakama aws init共通の土台を作成 (冪等)—
nakama aws acl add [IP|CIDR]許可 IP を追加 (省略時は自動検出)—
nakama aws acl list許可 IP を一覧—
nakama aws acl delete <IP|CIDR>許可 IP を削除—

環境の作成と情報

コマンド説明主なオプション
nakama aws create 開発環境を作成 --name <名前> (必須)、--instance-type <型> (必須)、 --bare、--preset <名前>、--setup <パス|https URL>、 --dotfiles <git URL>、--code-server-version <版>、 --with-admin、--with-role <ロール名>、--show-password、 --no-kiro (Kiro CLI / Kiro Crew の既定導入をスキップ)
nakama aws list一覧表示--show-nat (中継役も表示)
nakama aws info <名前>詳細表示--show-password
nakama aws setup rerun <名前>セットアップを再実行--setup、--dotfiles、--preset

アクセス

コマンド説明主なオプション
nakama aws kirocrew <名前>Kiro Crew の画面を code-server 経由で開く (自動ログイン)--no-auth、--print-url、--browser <コマンド>、--timeout <時間>
nakama aws kirocrew enable <名前>Kiro Crew の画面を開く仕組みを用意する (最初に 1 回)—
nakama aws kirocrew disable <名前>上の仕組みを取り外す—
nakama aws open <名前>ブラウザで開く (自動ログイン)--no-auth、--print-url、--browser <コマンド>、--timeout <時間> (既定 30s)
nakama aws connect <名前> [コマンド...]ターミナルに入る / コマンド実行。フラグは名前より前に置きます (名前より後ろは環境側で実行するコマンドとして扱われます)。コマンド実行は環境側の終了コードで終わります (nakama の失敗は 255)--tty、--retry <回数> (対話は既定 5、コマンド実行は既定 0)
nakama aws ssh setup <名前>公開鍵の登録と ssh 設定の生成--identity <公開鍵>、--no-key、--port <番号> (既定 22)
nakama aws ssh proxy <名前>ssh の ProxyCommand 用 (手で実行するものではありません)--port <番号>
nakama aws tunnel [start] <名前> -L <指定>ポート転送を開始-L <手元>:<相手> または -L <手元>:<ホスト>:<相手> (複数指定可)
nakama aws tunnel status [名前]転送状態 (名前を省略すると全件)—
nakama aws tunnel suggest <名前>転送候補のポートを提案—
nakama aws tunnel restart <名前>設定を変えず再接続—
nakama aws tunnel stop <名前>転送を停止—

運用

コマンド説明主なオプション
nakama aws start <名前>起動—
nakama aws stop <名前>停止—
nakama aws edit <名前>ディスク拡張 / 型変更--ebs <GiB>、--instance-type <型>、-y, --yes
nakama aws update <名前>OS と code-server を更新--keep <世代数>、-y, --yes
nakama aws backup create <名前>バックアップ作成--label <名札>、--note <メモ>、--keep <世代数>
nakama aws backup list [名前]バックアップ一覧 (省略で全件)—
nakama aws backup note <名前>メモを付ける--label (必須)、--note (必須)
nakama aws backup delete <名前>バックアップ削除--label (必須)
nakama aws restore <名前>バックアップから復元 (上書き)。環境を削除済みなら、同じ名前で作り直す (URL とパスワードは新しくなる)。完了後は停止状態なので start が必要--label <名札> (既定は最新)、-y, --yes。削除済みのときだけ: --instance-type <型>、--bare、--with-admin、--with-role <ロール>
nakama aws delete <名前>環境を削除 (15〜20 分)。土台は残ります--force、-y, --yes

診断とツール

コマンド説明主なオプション
nakama aws doctor環境を読み取り専用で点検共通の -o json が使えます
nakama aws cli shellaws CLI が動くシェルを開く (Windows 専用)。nakama.exe の場所も PATH の先頭に入ります--shell <実行ファイル>
nakama.exe をダブルクリックPowerShell のウィンドウを開き、nakama を打てるようにする (Windows 専用)。cli shell と同じプロキシの設定も入ります。設定はそのウィンドウの中だけです—
nakama completion <シェル>Tab キーでコマンドを補完できるようにする設定を出力します (PowerShell の例: nakama completion powershell | Out-String | Invoke-Expression)—

3. 環境変数

環境変数役割
HTTP_PROXY / HTTPS_PROXY / NO_PROXYプロキシの指定 (小文字も可)。設定されていれば OS の設定より優先されます
AWS_CA_BUNDLEaws CLI が使う証明書ファイル。nakama aws cli shell が自動で設定します
SSM_PLUGIN_PING_INTERVAL_SECONDS接続維持の信号の間隔 (秒、既定 300)。切断が多い環境で短くします
AWS_PROFILE / AWS_DEFAULT_PROFILEAWS 標準のプロファイル指定。nakama aws profile load で選んだものが優先されます
AWS_CONFIG_FILEAWS の設定ファイルの場所 (サインインセッションの読み取りに使われます)
XDG_CONFIG_HOMEnakama の設定の置き場所を変えたい場合に指定します (既定はホームの .config)
AWS_LOGIN_CACHE_DIRECTORYサインイン情報のキャッシュ場所を変えたい場合 (通常は不要)
NAKAMA_AWS_CLI_SHELLcli shell か、ダブルクリックで開いたウィンドウの中にいることを示す目印 (二重起動の防止に使われます。自分で設定するものではありません)

4. ファイルの置き場所

下の ~ は Windows では C:\Users\<あなた> です。nakama が作るファイルはすべて本人だけが読める権限 (0600) で作られます。

場所内容
~/.config/nakama/profiles.json保存したアカウントの一覧 (識別子のみ)
~/.config/nakama/aws_config上記から生成される AWS 形式の設定 (nakama 専用)
~/.config/nakama/tunnels/<名前>.jsonポート転送の状態 (tunnel stop で削除)
~/.config/nakama/ssh/<名前>.confssh 設定のスニペット
~/.config/nakama/aws-ca-bundle.pemcli shell が作る証明書ファイル (公開証明書のみ)
~/.aws/login/cache/サインイン情報のキャッシュ (AWS 公式の aws login と共有)
環境側の /var/log/nakama-provision.log初期セットアップの実行ログ
nakama が触らないもの

~/.aws/config、~/.ssh/config、Windows のレジストリ、ユーザー環境変数はいずれも書き換えません (ダブルクリックで開くウィンドウの PATH も、そのウィンドウの中だけの設定です)。ssh の設定は「スニペットを作るので、取り込むなら 1 行足してください」という方式です。

5. よく使う組み合わせ

初めて使う (1 回だけ)

nakama aws login
nakama aws init
nakama aws acl add
nakama aws create --name dev01 --instance-type t3.medium
nakama aws open dev01

毎日

nakama aws start dev01      # 使い始め
nakama aws open dev01
nakama aws stop dev01       # 使い終わり

場所 (回線) を変えたとき

nakama aws acl add          # いまの IP を追加

サインインの期限が切れたとき

nakama aws login
nakama aws tunnel restart dev01   # 転送を使っていた場合

手元の VS Code から使う (1 回だけ設定)

nakama aws ssh setup dev01
# 表示された Include 行を ~/.ssh/config に追加する
ssh nakama-dev01

大きな変更の前後

nakama aws backup create dev01 --label before-change --note "変更前"
# ... 作業 ...
nakama aws restore dev01 --label before-change   # 戻したいとき (上書きです)

消してしまった環境を戻す

nakama aws backup list                           # 削除した環境のバックアップも出る
nakama aws restore dev01                         # 同じ名前で作り直す (15〜20 分)
nakama aws start dev01

調子が悪いとき

nakama aws doctor
nakama aws doctor -o json     # 相談用
